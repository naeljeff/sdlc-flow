# Native agents and available models

Inspect actual host tools, model options, concurrency limits, file permissions, and observable agent/session metadata. These vary by host version and account. Do not install a controller or change global configuration to make a hypothetical route look available.

## Route an assignment

Keep the orchestrator on the user's selected model. Respect explicit worker preferences. Choose among genuinely available routes: faster models suit narrow, well specified checks; capable reasoning models suit ambiguity, consequential implementation, difficult diagnosis, and independent outcome review. Escalate from observed difficulty, not file count alone. Model diversity is useful additional coverage, not proof of accuracy.

Record requested and host/provider-reported model/effort separately, plus backend and agent ID when exposed. A model alias or the worker's own declaration is not upstream identity proof. Unknown telemetry stays unknown. Observe capability during a real bounded assignment; recheck after a relevant route/configuration change or failure rather than running paid probes before every dispatch.

| Host capability | Behavior |
| --- | --- |
| Spawn/message/wait and per-agent model selection | Use native heterogeneous Team mode within actual concurrency limits. |
| Parallel tools with inherited model only | Continue in parallel if appropriate and report the model-selection limitation. This does not meet an explicit heterogeneous-model requirement. |
| No agent tools | Use the sequential workflow with durable state; report unavailable delegation. |

If a required exact model is unavailable, keep work safe and report the concrete limitation. Do not silently substitute another model or manufacture a route proof. A rate limit preserves assignment state and follows observed retry timing; authentication/balance problems require correction. A model session ending is not task completion.

## Codex

Use the native collaboration tools exposed in the current host. Give bounded fresh context when requesting model overrides; follow the tool's fork/inheritance rules. Inspect the tool's declared models and slot counting rather than assuming a fixed global capacity. Use spawn for bounded assignments, follow-up/message for deltas, wait for results, and interrupt only owned workers when required.

A host's CLI can be used for a separate already-authenticated worker when that route is explicitly selected and tested. Use its documented model, workspace, sandbox, structured-event, and resume options; pass prompts by stdin and arguments as an argv list. This is a distinct backend and does not automatically inherit Desktop tools, permissions, or models. Record backend limitations.

## Claude Code

Use the exposed native Agent/Task and message/wait controls, with supported per-invocation or defined-agent model choices. A normal subagent may start without the main conversation or its memory; supply the versioned task packet explicitly. Keep task knowledge independent of host-specific auto memory. Apply the host's actual nesting and capacity limits.

An installed Claude CLI is not proof of authentication, tool availability, or a successful heterogeneous route. Validate the selected route without changing credentials/configuration. Do not register global agent definitions as a prerequisite to this package.

## Other hosts and external providers

Use the same assignment/result/memory protocol through verified native equivalents. Do not advertise a backend merely because its binary or catalog exists. Cross-provider dispatch needs an already configured route, allowed filesystem access, cancellation/ownership handling, compatible evidence, and a live test. It is optional and may require the user's existing provider setup; the skill alone does not supply models or credentials.
